# Пошаговый гайд: выкладываем diska на Render (бесплатно)

После прохождения всех шагов у вас будет публичная ссылка вида
`https://diska.onrender.com`, которую можно отправлять клиентам.
Банковская карта не нужна. Время: ~20–30 минут.

---

## Часть 1. Подготовка

Нужны два бесплатных аккаунта:

1. **GitHub** — хранилище кода. Регистрация: https://github.com/signup
2. **Render** — хостинг. Регистрация: https://dashboard.render.com/login
   (проще всего нажать «Get started with GitHub» и войти через GitHub-аккаунт)

Файлы проекта у вас уже распакованы, например в `C:\Users\DAL\Desktop\diska`.
Внутри должны лежать: `package.json`, `server.js`, папка `public`, `render.yaml`.

> Важно: папку `node_modules` и файл `data/db.json` загружать не нужно —
> Render сам установит зависимости и создаст пустую базу при первом запуске.

---

## Часть 2. Создаём репозиторий на GitHub

1. Зайдите на https://github.com и нажмите слева вверху **+ → New repository**.
2. В поле **Repository name** напишите `diska`.
3. Выберите **Public** (приватный на бесплатном тарифе Render тоже работает,
   но тогда нужно выдавать доступ приложению — для простоты выберите Public).
4. Ничего больше не отмечайте (НЕ ставьте галочку «Add a README file»).
5. Нажмите **Create repository**.

## Часть 3. Загружаем файлы в репозиторий (без команд, через браузер)

1. На открывшейся странице пустого репозитория нажмите ссылку
   **uploading an existing file**.
2. Откройте на компьютере папку `C:\Users\DAL\Desktop\diska`.
3. Выделите в ней **всё содержимое**: `package.json`, `package-lock.json`,
   `server.js`, `render.yaml`, `README.md`, папку `public` (и папку `data`,
   если она есть, но пустую — можно не добавлять).
   `node_modules` не перетаскивайте.
4. Перетащите выделенные файлы в окно браузера на GitHub — начнётся загрузка.
5. Внизу страницы нажмите зелёную кнопку **Commit changes**.
6. Готово — код на GitHub.

---

## Часть 4. Создаём сервис на Render

1. Откройте https://dashboard.render.com и нажмите **New + → Web Service**.
2. Выберите вкладку **Build and deploy from a Git repository** и нажмите
   **Next** (или сразу найдите репозиторий в списке).
3. Если GitHub попросит разрешение — нажмите **Configure/Install**,
   разрешите Render доступ к вашим репозиториям (можно только к `diska`).
4. В списке репозиториев найдите **diska** и нажмите **Connect**.

## Часть 5. Настройки сервиса

Render должен сам определить настройки из файла `render.yaml`.
Если поля заполнились — просто проверьте их. Если нет — впишите вручную:

| Поле | Значение |
|---|---|
| Name | `diska` (это станет частью ссылки) |
| Region | Frankfurt (Европа — ближе к России) |
| Branch | `main` |
| Runtime | Node |
| Build Command | `npm install` |
| Start Command | `node server.js` |
| Instance Type | **Free** |

5. Нажмите **Create Web Service**.

---

## Часть 6. Ждём первый запуск

1. Откроется страница сервиса с логами. Идёт сборка: 2–5 минут.
2. Успешный запуск выглядит так:
   ```
   diska запущен на http://0.0.0.0:10000
   ```
   (порт Render подставляет сам, это нормально — не 3000).
3. Сверху появится ссылка вида **https://diska.onrender.com** —
   это и есть адрес вашего сайта для клиентов.
4. Откройте её в браузере. Первая загрузка после паузы может занять
   до минуты — это «холодный старт» бесплатного тарифа, дальше всё быстро.

## Часть 7. Как обновлять сайт после правок

1. Внесите изменения в файлы локально.
2. На GitHub откройте нужный файл (например, `public/index.html`),
   нажмите иконку карандаша **Edit this file** справа вверху.
3. Внесите правки прямо в браузере (или просто загрузите новую версию файла
   через **Add file → Upload files**, согласившись на замену).
4. Нажмите **Commit changes**.
5. Render увидит изменение автоматически и передеплоит сайт за пару минут —
   следить можно на вкладке **Events/Logs**.

---

## Часть 8. Чтобы сайт не «засыпал» (бесплатно)

На бесплатном тарифе сервис останавливается после 15 минут без посетителей,
и первый человек ждёт ~1 минуту запуска. Решение — бесплатный пингалок:

1. Зарегистрируйтесь на https://uptimerobot.com (без карты).
2. **Add New Monitor → HTTP(s)**.
3. URL: `https://diska.onrender.com/healthz`
4. Интервал проверки: **10 минут**.
5. Сохраните. Сервис будет сам заходить на сайт, и тот не уснёт.

## ВАЖНО: про хранение данных на бесплатном тарифе

Сейчас заказы, клиенты и отзывы хранятся в файле `data/db.json`.
Диск бесплатного Render **временный**: при передеплое (Часть 7) или
перезапуске сервиса файл может обнулиться — данные пропадут.

Что с этим делать:

- **Для демонстрации и первых тестов** — можно оставить как есть.
- **Для постоянной работы с реальными заказами** — нужно подключить
  бесплатную внешнюю базу **MongoDB Atlas** (тоже без карты).
  Скажите — и я переделаю проект под неё: данные будут жить вечно,
  а деплой останется таким же простым.

## Если что-то пошло не так

| Симптом | Причина / решение |
|---|---|
| Ссылка не открывается, висит загрузка | Идёт холодный старт, подождите до 1 минуты |
| Render пишет `Build failed` | Проверьте, что загрузили `package.json` и `package-lock.json` в корень, а не во вложенную папку |
| `Cannot find module 'express'` | Build Command должен быть `npm install`, Start Command — `node server.js` |
| Страница открывается, но API не отвечает | Откройте Logs в Render, пришлите текст красной ошибки |
| Сайт работал, после обновления всё обнулилось | Это эфемерный диск — см. раздел про MongoDB Atlas |
| Хочу свой домен (diska.ru) | Settings → Custom Domains на Render; домен покупается отдельно (reg.ru и аналоги) |
